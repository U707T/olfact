## 已确认问题与修复

### 🟡 AI 任务可见取消与关闭不一致

位置：`ui/ai/AiActions.kt`、`AiSheet.kt`。
原来关闭/替换结果面板只收 UI，不取消仍在执行的 summarize/translate Flow；对生成式 API 会继续占网络和计算，用户无法主动停掉请求。现将协程 Job 绑定到面板；新面板替换、点击取消或 Activity 销毁时取消任务，取消不再显示为网络失败；异步读取网页文本期间也能取消，迟到的 JS 回调不会再启动请求。完成/失败后按钮转为关闭。

另使用 AI 模块的 `AiProvider.requiresApiKey()` 检查认证：本机 localhost 或显式 Authorization header 不再被 UI 强行要求单独 Key；普通在线供应商仍需 Key。

### 🟡 播放详情下载丢失嗅探请求认证头

位置：`ui/player/PlayerFragment.kt`。
播放器详情页“下载”原来只带当前页面 Referer；同一条 sniff 记录中 Cookie、Authorization、专用 UA、MIME 及其页面 Referer 没有传给下载模块，防盗链资源会出现 403。现从 `SnifferFeed` 按 URL 取请求上下文，优先采纳 sniff 的页面 URL/Referer、透传请求头、UA 和 MIME，并以当前页 URL 兜底。新增纯函数 `ui/player/MediaDownloadContext.kt` 与两条回归测试。

### 🟡 AI 供应商对话框错误处理

位置：`ui/settings/pages/AiFragment.kt`。
原生 positive-button 会在回调后自动关闭；输入无效或模块写入抛错时表单会消失，存储错误也没有说明。改为手动校验和关闭：名称、Base URL、模型必填；保存/删除/设当前失败时提示且保留原对话框/输入。编辑 Key 留空仍保留原 Key；页面补充本机 Ollama/localhost 可免 Key 的说明。AI 模块自己的本地持久化失败传播和 enabled-provider 选择规则由 AI 代理处理，本 UI catch 可处理实际抛出的错误。

### 🟡 脚本 GM 开关是未接线 UI

位置：`ui/settings/pages/ScriptFragment.kt`。
`GmBridge` 与 `GmJsInterface` 有实现，但 app/web 没有 `addJavascriptInterface(GmJsInterface, ...)` 接线；WebView 页面目前不能调用 GM API。原界面却提供可切换的“GM_* 桥接”开关并声称走 JsBridge，属于假可用功能。已改为不可点击的“暂未接入”状态说明，并修正文案；未擅自实现不在本批边界内的 WebView JS interface。

### 🟡 长按下载可预填网址（协作 API）

位置：`ui/download/AddDownloadSheet.kt`。
新增可选 `initialUrl` 参数并预填网址、把光标放在末尾；默认值保留原 `show(context) { ... }` 调用形式。并纠正 URI 编辑框 `InputType` 缺少 `TYPE_CLASS_TEXT` 的输入类型位。主代理可在其 `LongPressSheet` 调用处传 `initialUrl = target`，该文件未由本代理修改。

## 浏览器跨范围只读观察（已发主代理，不在本代理修改）

- `BrowserFragment.onResume` 消费 `RuntimeFlags.reloadPagesOnResume` 后只刷新当前可见 Surface；后续 `showTab()` 命中 `SurfaceCache` 且 URL 相同就直接重绑，不会再调用 `refreshConfig()`/reload。故在设置页更改 JS/图片/UA/字号/夜间配置后，非当前缓存标签可能保留旧 WebView 配置，之后切回仍旧。建议加全局配置代际或失效标记，激活 stale cache 时刷新配置/页面，不要让每次常规切标签都无条件重载。
- 正常 `WebBrowserSurface` 的 renderer-gone 可见路径保存容器、显示错误、重试时重建；缓存中的 renderer gone 后，重新激活时因 `view()==null` 创建新 View、URL mismatch 后 load，也可恢复。多数 Web 回调经动态 `host` 字段发出，detach 清空/reattach 替换，未见旧 binding 被异步回调直持有的明显路径。`BrowserFragment` 切换时先 detach 再选择新 tab，URL equality guard 可避免正常缓存页重复加载。无痕标记在创建 Surface 前由 `BrowserSession.select(boundTabId)` 对齐。无痕状态会跳过历史与标签落盘；单 WebView 的 Cookie/缓存仍与普通标签共享，这是 README 已列出的限制，不是本轮新缺陷。
- 低频维护线索：`WebBrowserSurface.onRenderProcessGone` 重新生成 tabId 前没有显式 `SessionSticky.closeTab(oldTabId)`，可能留下陈旧粘性会话至过期。
- `DefaultBrowserSurface` fallback 的 `onRenderProcessGone` 仅 destroy 并清空 WebView，没有错误 Host 回调或重试容器；正常安装会优先用 `WebBrowserSurfaceFactory`，但 fallback 条件下可能形成无恢复提示的空页。

以上只读结果已发父代理，浏览器文件未修改。

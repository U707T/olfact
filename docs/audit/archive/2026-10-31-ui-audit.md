# UI / 观感全量审计（2026-10-31，基于 rc6）

> 方法：读全部布局（12 个 XML + 大部分界面是 Kotlin 代码构建）、`core/uikit` 组件、
> 色板/尺寸/主题定义，并与 `docs/refs/` 里的原版截图逐屏对照。
> **限制**：沙箱无 KVM/adb，没跑真机；尺寸对比是按截图比例换算（原版截图 860px 宽 ≈ 360dp，
> 约 2.4 px/dp），误差 ±2dp。所有结论都能在代码里定位，但最终观感建议在真机复核。

## 0. 结论摘要

| 维度 | 评分 | 一句话 |
|---|---|---|
| 与原版的一致性 | ★★★★☆ | 菜单/底栏/设置页的图标与尺寸已对齐；首页比例偏大，两处弹层交互与原版不同 |
| 设计系统化 | ★★☆☆☆ | 双色板、双主题并存；字号 11.5~17 混用；5 个设计令牌定义了没人用 |
| 视觉层次与密度 | ★★★☆☆ | 设置/下载页层次清晰；首页元素偏大、信息密度低于原版 |
| 状态完整性 | ★★★☆☆ | 4 个列表有空态；无错误态/骨架屏；加载态只有下载页一根细条 |
| 无障碍 | ★★☆☆☆ | 提示文字对比度 2.68:1 不达标；代码构建的图标按钮基本没有 `contentDescription` |
| 暗色模式 | ★★★☆☆ | 色板齐全，但两张插画是亮色位图、夜间主题覆盖不全 |
| 动效 | ★★★★☆ | 时长/曲线克制（140~180ms），没有花哨动画；缺预测性返回的共享元素 |

**一句话**：功能与"像不像"已经过关，**主要短板在设计系统的收敛**（颜色/字号/组件三套口径）
和**两处与原版不同的弹层交互**（长按菜单、添加下载对话框）。

## 1. 设计系统层

### 1.1 双色板并存（🔴 结构问题）

| 位置 | 内容 |
|---|---|
| `app/src/main/res/values/colors.xml` | `page_bg #F2F2F2`、`card #FFF`、`text_primary #212121`… |
| `core/src/main/res/values/uikit_colors.xml` | `uikit_page_bg #F2F2F2`、`uikit_card #FFF`、`uikit_text_primary #212121`… |

两套色值当前**完全相同**，但各模块各用一套（app 布局用 `@color/card`，uikit 组件用 `@color/uikit_card`）。
改一次品牌色要改两个文件，漏一个就出现"同一页面两种灰"。
**建议**：保留一套（core 的 `uikit_*` 作为唯一来源），app 侧只留语义别名或直接引用。

### 1.2 双 `Theme.Olfact` 定义（🔴 结构问题）

- `core/src/main/res/values/styles.xml`：parent `Theme.MaterialComponents.DayNight.NoActionBar`，
  定义了 `colorSurface`/`dialogCornerRadius`/状态栏色等一整套。
- `app/src/main/res/values/themes.xml`：同名 `Theme.Olfact`，parent 换成 `Theme.AppCompat.DayNight.NoActionBar`。

App 模块资源优先，所以**运行时用的是 app 那份**，core 那份是死代码；而 app 的 `values-night/themes.xml`
只覆盖了 10 个属性，漏了 `windowLightNavigationBar` 与 `windowAnimationStyle`（夜间切页动画会丢）。

### 1.3 字体阶梯没有落地（🟡）

`uikit_dimens.xml` 定义了 28 / 20 / 17 / 16 / 15 / 13 / 12 / 11 sp 八档，实际代码里出现的是：

```
14sp ×10   12sp ×8   13sp ×7   15sp ×3   12.5sp ×2   11.5sp ×2   22sp   16sp
```

`12.5sp`、`11.5sp` 这种半档是视觉上最难对齐的来源（不同密度下会跳像素）。
**建议**：收敛成 4 档（12 辅助 / 14 正文 / 17 行标题 / 28 页面标题），删掉 11.5、12.5、13。

### 1.4 令牌空转（🟡）

定义了但全仓 0 引用的令牌：`uikit_text_tiny`、`uikit_text_label`、`uikit_text_header`、
`uikit_icon_small`、`uikit_icon_large`、`uikit_bottom_bar_height`（底栏高度是代码里写死的 50dp）。
令牌存在但不强制，等于没有——**建议把组件里的字面量全部换成 `@dimen`/`R.dimen`**。

### 1.5 图标

| 项 | 现状 |
|---|---|
| 来源 | 菜单/底栏/设置页共 34 个全部来自安装包（`orig_m_*` / `orig_b_*` / `orig_s_*`）✅ |
| 尺寸 | 底栏 30dp、九宫格 26dp、设置行 24dp、列表行 22dp、箭头 16dp；同一视觉重量有三种尺寸 |
| Tint | 大多数走 `imageTintList` 跟随主题 ✅；AI 两枚保留原色 ✅ |

尺寸差异本身可接受（不同位置有不同基准），但**同一层级**（如"设置行图标 24dp vs 列表行 22dp"）
建议统一到 24dp，减少视觉跳动。

### 1.6 间距

布局里 dp 出现频次：16dp ×30、12dp ×12、10dp ×11、8dp ×11、6dp ×7、4dp ×7、20dp ×6。
基本是 4 的倍数，但 6/10/12 混用，没有严格的 4/8/16/24 栅格。
**建议**：卡片内边距 16、行内左边距 16、元素间隔 8/12、区块间隔 24。

## 4. 功能性的 UI bug（🔴 用户可见）

| # | 现象 | 证据 | 影响 |
|---|---|---|---|
| 1 | **「底部栏样式」开关无效**：设置里选"胶囊/纯图标"，底栏渲染完全一样 | `BottomBar.configure(items, style)` 只把 `style` 存了字段，`buildIconSlot/buildCountSlot/buildPill` 没有任何分支 | 用户改了没反应，像坏了 |
| 2 | **底栏隐藏时没有底部安全区**：进设置/列表页（`showsBottomBar=false`）后，内容可以滚到系统导航栏下面 | `MainActivity.applyInsets()` 只给 `bottomBar` 加 `paddingBottom=bars.bottom`，`container` 只有 top | 最后一行被手势条/导航栏压住 |
| 3 | 长按菜单是底部弹层，单手可达但与原版位置不同 | `LongPressSheet.show()` 用 `Sheet` | 与 §2 一致，属设计取舍；若要还原需改成 `PopupWindow` 锚定 |

## 5. 无障碍与对比度

按 WCAG AA（正文 4.5:1、大字 3:1）实测：

| 组合 | 对比度 | 判定 |
|---|---|---|
| 日间 正文 `#212121` / 页面 `#F2F2F2` | 14.38:1 | ✅ |
| 日间 次要 `#757575` / 卡片 `#FFF` | 4.61:1 | ✅（擦线） |
| 日间 提示 `#9E9E9E` / 卡片 `#FFF` | **2.68:1** | ❌ 用于 11~13sp 的说明文字，读不清 |
| 日间 品牌 `#109D58` / 白 | **3.51:1** | ⚠️ 只够 18pt+ 大字；我们用它做 14sp 链接/按钮文字 |
| 夜间 提示 `#757575` / 卡片 `#1C1C1E` | 3.69:1 | ⚠️ |
| 夜间 品牌 `#2FB877` / 卡片 | 6.68:1 | ✅ |

**建议**：`text_hint` 提到 `#8A8A8A`（约 3.4:1，仍偏弱）或只在非信息性文案上用；
品牌绿做正文时改用 `brand_dark #0C7A44`（约 5.4:1）。

其它：

- **contentDescription**：布局内的 16 个 `ImageView` 有 14 个带描述（2 个是 `@null` 装饰图），
  覆盖率不错；**缺口在代码构建的图标按钮**——`core/uikit` 里只有 `PageHeader` 的返回/动作按钮
  和 `UrlBar` 的 DNS 状态图标带描述，**底栏 5 个槽（`ICON_ONLY` 时没有任何文字）、
  `NineGrid` 单元格图标、`ListRow` 图标都没有**。
  有文字标签的格子 TalkBack 还能读出来，纯图标槽位只会念"按钮"。
- **触摸目标**：底栏 50dp、SettingItem 56dp、ListRow 64dp ✅；扫码页"手动输入地址"按钮
  padding 10dp + 14sp ≈ 40dp，略低于 48dp 建议值。
- **状态**：4 个列表有空态；**没有错误态**（网络失败只 toast）、没有骨架屏/占位图。

## 6. 暗色模式

- 色板齐全（`values-night/colors.xml` + `uikit_colors.xml`），品牌绿夜间换成 `#2FB877` ✅。
- 两张位图是亮色：`home_scenery.webp`（浅色天空）与 `home_bird.webp`（白鸟 + 浅色气泡），
  夜间模式下会像"贴了一张白纸"。
- 夜间主题只覆盖了少量属性，`windowLightNavigationBar` / 动画样式回落到默认。
- 图标 tint 跟随主题 ✅，未出现"夜间看不清"的黑图标。

## 7. 动效

- 页面切换 180ms 滑入 + 淡出，返回反向；底栏出现 180ms / 收起 140ms；Sheet 自底部升起。
  时长在 140~200ms 的舒适区，曲线是默认 `decelerate`，没有弹跳/过冲 ✅。
- 缺：预测性返回的"跟手"动画（`OnBackInvokedCallback` 已有，但没有共享元素/缩放衔接）；
  列表项没有入场动画（可接受，浏览器类应用应克制）。

## 8. 修复清单（按优先级）

**P0（用户能直接感知为"坏了"）**
1. 底栏样式开关无效 → `BottomBar` 里按 `style` 渲染：`PILL` 显示胶囊，`ICON_ONLY` 把胶囊槽替换成图标。
2. 底栏隐藏时内容压到导航栏 → 把底部 inset 同时给 `container`（或给根布局统一 `paddingBottom`）。
3. 提示文字对比度 2.68:1 → 调 `text_hint` / `uikit_text_hint`。

**P1（与原版观感差距最大）**
4. 首页插画与快捷入口尺寸回调到原版比例（120dp / 36dp）。
5. 长按菜单改回锚定浮层（或至少在设置里给"底部弹层/浮层"选项）。
6. 添加下载改回居中对话框，补"文件后缀""大小提示""内置/其它下载器"。
7. 下载 tab 加绿色下划线指示条。

**P2（设计系统收敛）**
8. 合并双色板、双主题；把 `Theme.Olfact` 只留在 core 或只留在 app。
9. 字号收敛到 4 档，删掉 11.5/12.5；令牌真正被引用。
10. 给代码构建的图标按钮补 `contentDescription`；补错误态。
11. 夜间模式：插画加一层 30% 黑色遮罩或换夜间版素材。
12. 把 410 处 Kotlin 硬编码文案抽到 `strings.xml`（顺带解决 lint 的 31 处 HardcodedText）。

## 9. 建议的规范（可直接落到 `uikit_dimens`）

```
字号：28 页面标题 / 17 行标题 / 14 正文 / 12 辅助（删除 11.5、12.5、13、15 的一次性用法）
间距：4 / 8 / 12 / 16 / 24；卡片内边距 16，行左右 16，区块间 24
圆角：卡片 16 / 弹层 20 / 按钮 12 / 胶囊 full
图标：20（内联）/ 24（行）/ 30（底栏）
颜色：只用 core 一套；正文 14.38:1、次要 4.6:1、提示 ≥3.5:1、品牌≥4.5:1（小字用 brand_dark）
```

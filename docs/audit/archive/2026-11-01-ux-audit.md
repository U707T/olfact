# 用户体验 / 操作逻辑审计（2026-11-01，rc6 基线）

> 方法：逐屏读代码路径 + 把 66 个设置项与「谁真正读它」做映射 + 对导航/返回/空态/错误态/反馈逐项走查。
> 限制：沙箱无 KVM/adb，无法真机点击；凡是需要真机确认的结论都标了「待真机验证」。
> 结论按「用户会不会被卡住/被骗」排序，不是按代码量排序。

## 0. 一句话结论

功能主干是通的，但**交互层存在系统性「说谎」**：29 个开关改了没有任何效果，
下载列表 4/6 个菜单项是占位文案，切标签会整页重载，出错时没有任何提示。
这些比缺功能更伤体验——用户会认为「这应用坏了」，而不是「这功能没做」。

## 附录 A：设置项 ↔ 生效情况（66 项，脚本核对）

分类口径：以「`K.<KEY>` 是否出现在设置页渲染文件之外」为准，再看是读还是写。

| 类别 | 数量 | 清单 |
|---|---|---|
| **真正驱动逻辑** | ~27 | NIGHT_MODE、BOTTOM_STYLE（仅启动时读）、RESTORE_TABS、SEARCH_ENGINE、SEARCH_CUSTOM、HISTORY_LIMIT、TEXT_ZOOM、NIGHT_WEB、NO_IMAGE、DESKTOP_MODE、JS_ENABLED、SNIFF_ENABLED、AD_ENABLED、AD_COSMETIC、AD_COUNT_TOTAL、AD_COUNT_TODAY、DOH_ENABLED、DOH_MODE、DOH_UPSTREAM、DOH_UPSTREAM_CUSTOM、DOH_RULES、BACKUP_WEBDAV_URL/USER/PASS、BACKUP_AUTO、PRIVACY_CLEAR_ON_EXIT |
| **只回显、不生效**（开关能翻，行为不变） | 5 | SCRIPT_ENABLED、SCRIPT_GM_BRIDGE、AI_SUMMARY、AI_TRANSLATE、AI_SELECTION（都只在设置页读出来画开关） |
| **只写不读** | 2 | PLAYER_SPEED、BACKUP_LAST_AT |
| **死开关**（只出现在设置页） | 29 | FONT_SCALE、EYE_CARE、BACK_NO_RELOAD、SUGGEST_SOURCE、SEARCH_CLIPBOARD、ALLOW_OPEN_APP、ALLOW_LOCATION、CONTINUE_PLAY、FORCE_NEW_WINDOW、FULLSCREEN_SCROLL、SWIPE_BACK、DOUBLE_TAP_ZOOM、DL_THREADS、DL_CONCURRENT、DL_WIFI_ONLY、DL_NOTIFY、DL_AUTO_RENAME、DL_M3U8_MERGE、SNIFF_TIP、SNIFF_FILTER_SMALL、PLAYER_GRAVITY_ROTATE、PLAYER_PIP、PRIVACY_DO_NOT_TRACK、PRIVACY_BLOCK_THIRD_PARTY、LANGUAGE、NOTIFY、DEV_MODE、LOG_LEVEL、WEB_LOG |
| **完全没被引用** | 3 | PAGE_ZOOM、AD_COUNT_DAY、DOH_STICKY |

> 复现方式：`grep -rn "K\.<KEY>" app/src/main/java | grep -v SettingsSpecs.kt`，为空即为死开关。
> 其中「脚本主开关」「AI 三开关」虽然能读到，但只用来回显选中态，改了对注入/总结没有任何影响——最容易被当成 bug 的一类。

## 附录 B：建议修复顺序（两周）

1. **第 1 天**：死开关先做减法——把 29 个里不打算实现的从界面移除，剩下的排期接上；同时删掉过期文案（P0-1/3/5）。
2. **第 2~3 天**：下载设置合一（P0-2）+ 下载列表菜单实现或删除（P0-3）。
3. **第 4~5 天**：设置立即生效（P0-4）+ AI 断头路（P1-9）+ 错误页（P1-7）。
4. **第 6~8 天**：标签切换复用 surface（P1-6）——这是日常使用体感最大的一项。
5. **第 9~10 天**：脚本导入、扫码出口、删除撤销、备份重启等 P1 收尾。
6. 之后：一致性（P2）与打磨（P3）。
